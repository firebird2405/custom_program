# STORE-GUIDE — 쁘띠캘린더 MS Store 출시 가이드 (사용자용)

> 이 문서는 **사용자가 직접 해야 하는 파트너 센터 작업**과, 값을 전달받은 뒤
> **우리(에이전트) 쪽에서 진행되는 절차**를 순서대로 안내해요.
> 사용자 작업은 딱 3가지예요: ① 개발자 등록(무료) → ② 앱 이름 예약 → ③ identity 값 3개 복사·전달.
> 계약 근거: `protocol/SCORECARD.md` rev.6 A48②·A50, 스펙 정본 `protocol/grader/tests/a48-store-readiness.spec.js`.

---

## 한눈에 보는 흐름

```
[사용자] 1. 파트너 센터 개발자 등록 (무료, 1회)
[사용자] 2. 앱 이름 예약 — "쁘띠캘린더"
[사용자] 3. 제품 ID 화면에서 값 3개 복사 → 에이전트에게 전달
[에이전트] 4. electron-builder.yml 기입 → npm run dist:appx → A48②·A50·A46 검증
[사용자+에이전트] 5. 파트너 센터 제출(패키지 업로드 + 스토어 등록 정보) → 심사(보통 1~3일)
```

---

## 1단계 — Microsoft 파트너 센터 개발자 등록 (무료, 1회)

1. 브라우저에서 **https://partner.microsoft.com/dashboard/registration** 을 열어요.
2. 평소 쓰는 **Microsoft 계정**으로 로그인해요. (없으면 무료로 새로 만들 수 있어요)
3. 프로그램 선택 화면이 나오면 **"Windows 및 Xbox" (앱 개발자 프로그램)** 을 선택해요.
4. 국가/지역: **대한민국**, 계정 유형: **개인(Individual)** 을 선택해요.
   - 개인 유형이면 사업자 정보 없이 등록돼요. 법인(Company)은 서류 검증이 더 걸려요.
5. **게시자 표시 이름(Publisher display name)** 을 입력해요 — 스토어에서 "제작자"로 보이는 이름이에요.
   (예: `firebird2405`. 나중에 변경 가능해요. 이 값이 뒤의 `publisherDisplayName`이 돼요.)
6. 등록비는 **무료**예요 — 2025년 9월부터 개인 개발자 등록비(종전 $19)가 폐지됐어요
   (Windows Developer Blog 2025-09-10, `protocol/MARKET.md` 부록 C 실사). 신분증·셀피 경량 검증만 진행돼요.
   만약 결제 화면이 나오면 정책이 다시 바뀐 것이니, 진행을 멈추고 알려 주세요.
7. 등록이 끝나면 **https://partner.microsoft.com/dashboard** 대시보드에 들어갈 수 있어요.
   (개인 계정은 보통 즉시~몇 시간 안에 승인돼요.)

---

## 2단계 — 앱 이름 예약: "쁘띠캘린더"

1. 파트너 센터 대시보드에서 왼쪽 메뉴(또는 홈 타일)의 **"앱 및 게임" (Apps and games)** 을 클릭해요.
2. 오른쪽 위 **"+ 새 제품" (New product)** → 제품 종류는 **"앱(MSIX)"** 을 선택해요.
   - EXE/MSI 형식이 아니라 **MSIX** 이에요 — 우리 패키지(.appx)가 이 형식이에요.
3. 이름 입력 칸에 **`쁘띠캘린더`** 를 입력하고 **"제품 이름 예약" (Reserve product name)** 을 눌러요.
   - 이미 누가 쓰고 있다는 오류가 나면 `쁘띠캘린더 - 포스트잇 월` 처럼 변형해서 예약하고 알려 주세요.
4. (**선택 — 해도 되고 안 해도 돼요**) **제품 관리 → 제품 이름 관리**에서 **`PetitCalendar`** 를
   추가 이름으로 예약해 두는 걸 권해요. 지금 당장 쓰지는 않고, **나중에 남이 이 이름을 채가지 않도록**
   자리만 잡아 두는 거예요 (예약은 무료예요).
   - **영어 리스팅은 이번 판에서 내지 않아요** (2026-08-21 결정 — 발주 #27). 앱 화면이 전부 한국어라서
     영어권에 내놓으면 "읽을 수가 없다"는 1점 리뷰만 쌓여요. 그래서 `protocol/MARKET.md` 의 G1 게이트도
     **한국어 마켓 단독**(리뷰 5건)으로 되돌렸어요.
   - 영문 설명문 `store-assets/store-description.en.md` 와 영문 캡션 컷 `store-assets/en/` 은 **지우지 않고**
     보관해 둬요 — **앱 화면을 영어로 번역하는 발주를 한 다음에** 그대로 씁니다.

> 이름을 예약하는 순간 Microsoft가 이 앱 전용 **identity 값**(다음 단계에서 복사할 3개)을 만들어 줘요.

---

## 3단계 — identity 값 3개 확인 후 전달 (가장 중요!)

1. 방금 예약한 **쁘띠캘린더** 제품을 클릭해 들어가요.
2. 왼쪽 메뉴에서 **"제품 관리" (Product management)** → **"제품 ID" (Product identity)** 를 클릭해요.
3. 화면에 아래와 같은 값들이 표로 보여요. **이 중 3개를 그대로 복사**해서 에이전트에게 전달해 주세요.

| 화면에 보이는 라벨 | 예시 형태 | 우리가 넣는 곳 (`electron/electron-builder.yml`) |
|---|---|---|
| **Package/Identity/Name** | `12345Firebird.PetitCalendar` | `appx.identityName` |
| **Package/Identity/Publisher** | `CN=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` | `appx.publisher` |
| **Package/Properties/PublisherDisplayName** | `firebird2405` | `appx.publisherDisplayName` |

전달할 때는 이렇게 3줄 그대로 붙여 넣어 주시면 돼요:

```
Package/Identity/Name: (복사한 값)
Package/Identity/Publisher: (복사한 값)
PublisherDisplayName: (복사한 값)
```

주의할 점:
- **Publisher는 반드시 `CN=` 으로 시작**해요. `CN=` 을 빼고 GUID만 복사하지 않도록 해 주세요.
- 값을 임의로 바꾸면 안 돼요 — 스토어 업로드 때 파트너 센터 값과 1글자라도 다르면 거절돼요.
- 같은 화면의 다른 값들(Package SID, Store ID 등)은 지금 단계에선 필요 없어요.

---

## 4단계 — 값 전달 후: 우리 쪽 절차 (사용자는 지켜보기만 하면 돼요)

에이전트가 아래를 순서대로 진행해요.

1. **기입** — `electron/electron-builder.yml` appx 절의 "★★ 여기만 채우면 완성" 3줄
   (`identityName` · `publisher` · `publisherDisplayName`) 주석을 해제하고 전달받은 실값을 기입.
2. **빌드** — `cd electron ; npm run dist:appx`
   - 1단계 가드(`check-appx-identity.js`)가 identity 3개 값의 기입·형식(`CN=` 시작 등)·플레이스홀더 여부를
     검사해요. 미기입 상태로 실행하면 한국어 안내와 함께 안전하게 중단돼요.
   - 통과하면 `electron-builder --win appx` 가 `electron/dist/` 에 `.appx` 패키지를 만들어요.
3. **검증 게이트** (채점기 — `cd protocol\grader ; npm test`)
   - **A48②**: 패키지 안 `AppxManifest.xml` 의 Identity·DisplayName이 실값·브랜드(쁘띠캘린더/PetitCalendar)와
     일치하고 플레이스홀더가 없는지.
   - **A50**: 실제 테스트 설치(Add-AppxPackage) → 시작 메뉴 등록·표시 이름·아이콘 확인 → 즉시 제거.
     (스토어 서명 전 패키지는 로컬 설치가 서명 정책에 막힐 수 있어요 — 그 경우 명시적 SKIP으로 기록되고,
     실물 검증은 스토어 심사가 대신해요. 실패도 통과도 아닌 "환경상 건너뜀"이라 걱정 안 해도 돼요.)
   - **A46**: 패키지 크기 상한(≤120MB)과 개인 데이터 미동봉(backups/.edge/protocol/로그/저장 데이터 0) 검사.
   - **A44**: 앱 런타임 외부 요청 0 유지 확인.
4. **보고** — 전 게이트 결과를 정리해서 보고해요. 여기까지 green이면 제출 준비 완료예요.

## 5단계 — 스토어 제출

1. 파트너 센터 → **쁘띠캘린더** 제품 → **"제출 시작" (Start your submission)** 을 클릭해요.
2. 섹션별로 채워요 (에이전트가 준비해 둔 자료를 그대로 쓰면 돼요):
   - **가격 책정 및 가용성**: 가격 **무료**, 판매 지역 기본값(전체) 유지.
   - **속성**: 카테고리 **개인 설정(Personalization)**.
     (생산성(Productivity)이 아니에요 — `LAUNCH-KIT.md` 대원칙 "생산성 앱으로 소개하지 않는다"와
     정합: 생산성 매대는 TickTick·Notion 지형이라 우리 무기(다꾸·감성·꾸미기)가 안 보여요.)
   - **연령 등급**: 설문에 답하면 자동 산정돼요 — 우리 앱은 수집·채팅·구매 없음이라 전체 이용가로 나와요.
   - **패키지**: `electron/dist/` 의 **`.appx` 파일을 업로드**해요.
     - 인증서 구매·서명은 필요 없어요 — 스토어 제출용 패키지는 심사 통과 후 **Microsoft가 대신 서명**해요.
   - **스토어 등록 정보**: **한국어만** 등록해요 (영어 리스팅은 보류 — 위 2단계 4번 참고, 발주 #27).
     설명문은 `store-assets/store-description.md` 의 **본문("한 줄 소개"부터 "문의" 줄까지)** 을
     그대로 붙여 넣어요. (맨 위의 `>` 인용 메모와 구분선(`---`) 아래 검색어 절은 내부 지침이라
     붙여 넣지 않아요.)
     - **검색어(Search terms) 7칸을 꼭 채워요** — 같은 문서 아래쪽 "스토어 검색어" 표의 7개를 순서대로
       입력하면 돼요. 이게 스토어에서 우리 앱이 발견되는 **유일한 공짜 수단**이에요.
       (2026-08-24 개정판 기준이에요 — '포스트잇'은 3M 등록상표라 검색어에서 뺐어요. 표에 없는
       옛 검색어를 임의로 추가하지 마세요.)
     - **스크린샷은 6장**이에요 — **`store-assets/kr/` 의 국문 캡션판**을 `store-assets/README.md`
       §2-2 의 순서대로 올려요. (목록 화면에서 썸네일은 손톱만 해서, 캡션 띠가 없으면 1초 안에
       기능이 안 읽혀요. 합성 컷·구버전 화면 컷은 **올리지 않아요** — 실제 화면과 다르면
       "설명과 다르다" 리뷰가 붙어요.)
   - **개인정보처리방침 URL**: 우리 앱은 **아무 정보도 수집하지 않아요**(A48③·A44 검증).
     설문에서 "개인 정보에 접근하지 않음"으로 답하면 URL 없이 통과되는 경우가 많고,
     URL이 꼭 요구되면 GitHub 저장소의 개인정보처리방침 파일 주소를 쓰면 돼요 (에이전트가 안내).
3. **"스토어에 제출" (Submit to the Store)** 을 눌러요. 심사는 보통 **24~72시간** 걸려요.
4. 통과하면 스토어에 공개돼요. 거절되면 사유가 메일로 와요 — 사유를 에이전트에게 전달해 주시면 수정 후 재제출해요.

## 자주 묻는 질문

- **돈이 나가나요?** — 아니요. 2025년 9월부터 개인 개발자 등록도 무료예요. 연회비·제출비·심사비도 없어요.
- **코드 서명 인증서를 사야 하나요?** — 아니요. 스토어 배포는 Microsoft가 서명을 대신해 줘요.
  (스토어 밖 배포용 NSIS 설치본에만 서명 이슈가 있는데, 그건 이 가이드 범위 밖이에요.)
- **빌드된 .appx 를 더블클릭했는데 설치가 안 돼요.** — 정상이에요. 서명 전 패키지라 로컬 설치가 막혀요.
  로컬 확인이 꼭 필요하면 Windows 설정 → 개발자 모드를 켜야 하는데, 스토어 제출에는 필요 없어요.
- **identity 값을 잘못 전달했으면요?** — 파트너 센터 제품 ID 화면에서 언제든 다시 복사할 수 있어요.
  값만 다시 주시면 재빌드는 몇 분이면 돼요.
- **앱 이름을 나중에 바꿀 수 있나요?** — 새 이름을 추가 예약한 뒤 표시 이름을 바꾸는 방식으로 가능해요.
  단 `Package/Identity/Name` 은 최초 예약 기준으로 고정이에요.
